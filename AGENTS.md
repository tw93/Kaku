# Kaku Website Agent Guide

This is the website checkout on the `vercel` branch, not the app source tree. Read `DESIGN.md` for design tokens and source/generated ownership before editing.

- Docs update flow (features, Guide, EN/ZH parity, version bumps): `.agents/skills/product-docs`; `.claude/skills/product-docs` links to it.

- `index.html`, `zh/`, and `docs/` contain the site; `vercel.json` owns routing.
- Prose Markdown twins come from `scripts/build_markdown.py`; `index.md` and `zh/index.md` are hand-maintained exceptions. `scripts/build_feed.py` generates the page feed. `scripts/build_releases.py` generates `feed.xml`, `feeds/releases.json`, and the changelog pages from stable GitHub releases.
- Run the public-facts CI checks: `python3 scripts/test_blog_pipeline.py`, `python3 scripts/build_blog.py --check`, `python3 scripts/build_markdown.py --check`, `python3 scripts/build_feed.py --check`, `python3 scripts/build_releases.py --check`, `python3 scripts/highlight.py --check`, `python3 scripts/check_public_facts.py`, `python3 scripts/check_sitemap.py`, and `python3 scripts/build_fonts.py --check` (fonttools and brotli; rerun `python3 scripts/build_fonts.py` after Chinese copy changes) (Markdown, Pygments and Pillow are required). Validate dependency changes in a fresh virtual environment: `build_blog.py` reads diagram dimensions through Pillow, so an already-populated local environment can hide a missing CI dependency. These verify generated files, published app facts, and sitemap lastmod/loc rules, not live website deployment. After HTML edits, regenerate markdown and the page feed, and bump the affected entries' `lastmod` in `sitemap.xml`, `sitemap-index.xml`, and `schemamap.xml` to the content date. Dates follow each page or discovery file separately; a blog publication must not redate unchanged docs. Blog article dates follow their Markdown source, since related-post navigation changes on every publication. Set `modified` when editing a published article; never change its original `date`. The blog generator maintains the sitemap index and blog-related schema entries too. The pipeline test publishes and commits two consecutive days only in a disposable repository, then verifies same-day reruns and Markdown links.
- Blog: sources are `content/blog/<slug>.{en,zh}.md` plus the queue `content/blog/index.json`; `scripts/build_blog.py` writes `blog/`, `zh/blog/`, their `.md` twins and feeds, and the marked blog blocks of `sitemap.xml`, `llms.txt` and `zh/llms.txt`, so never hand-edit those. Posts publish one per day: the `Blog Publish` workflow on `main` of tw93/Kaku runs `scripts/publish_next_post.py` here at 09:00 Beijing, dates the next queued post and pushes (maintainer decision 2026-10-17, a same-day batch reads as fake). On 2026-10-19 the maintainer had the whole queue backdated in queue order, one post per day from 2026-09-19 to 2026-10-19, and published at once; posts queued later go out through the daily workflow again. Do not redate a live post unless the maintainer asks. Each post has a 1600x900 cover in `img/blog/cards/<slug>.webp` (image model, recipe in `DESIGN.md`) and its diagrams come from `scripts/build_blog_diagrams.py`, which fails when text would render under 12px. Write the Chinese body separately in the maintainer's voice, not as a translation, and only link from a post to posts queued before it. Run `python3 scripts/build_blog.py --check` with the checks below.
- Canonicals, hreflang, breadcrumb `item`s, `og:url` and internal links use the slashless URL (`/docs`, `/zh`, `/zh/docs`), because `trailingSlash: false` 308s the slashed form; a slashed canonical made Google keep `/docs/` as an alternate and leave other docs pages unknown (fixed 2026-10-15). `vercel.json` also 308s `www.kaku.fun` to the apex, since Google had indexed a www copy; `/` needs its own rule, because `/:path*` let the www home page through with a 200 (2026-10-19).
- Pages with a Chinese twin carry both `zh-CN` and `zh-Hans` hreflang: `zh-CN` alone names mainland China, so Simplified readers elsewhere are not matched to it.
- Keep English and Chinese counterparts, public version facts, and generated discovery files aligned with the changed source.
- Preserve unrelated website work. Publishing this branch is a website delivery action; do not use app release commands here.
